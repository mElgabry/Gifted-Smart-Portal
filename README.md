الإدارة المركزية لمدارس التربية الخاصة - الإدارة العامة للموهوبين والتعلم الذكي

## نظرة عامة
منظومة رقمية متكاملة مصممة طبقاً لـ:
1. متطلبات الكتاب الدوري رقم (55) لسنة 2016.
2. النشرة التوجيهية للعام الدراسي 2026/2027 «موهبتي ... استعدادي للابتكار».
3. الهيكل التنظيمي للمديريات والإدارات التعليمية والـ 164 مركز رعاية موهوبين على مستوى الجمهورية.
4. الهوية البصرية المعتمدة (شعار وزارة التربية والتعليم والتعليم الفني + شعار الإدارة العامة للموهوبين والتعلم الذكي).

## دليل حفظ البيانات ونقل المجلد بين الأجهزة (Portable Data Guide)

### 1. سبب عدم انتقال البيانات سابقاً عند نسخ المجلد
كان الموقع يعتمد حصرياً على الذاكرة المحلية للمتصفح (`localStorage`). هذه الذاكرة يتم تخزينها داخل ملفات تعريف المتصفح الخاصة بكل حاسوب على حدة، ولا تتواجد داخل مجلد الموقع نفسه. لذا عند نسخ المجلد لجهاز آخر، كان المتصفح على الجهاز الجديد يقرأ البيانات الافتراضية الأولية فقط.

### 2. التحديثات والحلول المطبقة لضمان بقاء البيانات داخل المجلد:
تمت ترقية المنظومة لتشمل نظام حفظ تلقائي وتكاملي متعدد الطبقات:
1. **الخادم المحلي الخفيف للحفظ التلقائي المباشر**:
   - تم توفير ملف **`تشغيل_البوابة.bat`** (و **`start.bat`**): بمجرد النقر المزدوج عليه في أي جهاز يعمل بنظام ويندوز، يتم تشغيل خادم محلي تلقائياً (عبر Python أو عبر PowerShell المدمج في ويندوز دون الحاجة لتثبيت أي برامج).
   - يقوم الخادم بحفظ أي طالب جديد أو تعديل في المراكز أو سجل التدقيق فوراً ومباشرة داخل ملف **`data/portal_database.json`** وملف **`data/saved_data.js`** داخل المجلد.
   - عند نسخ المجلد بالكامل لأي جهاز آخر، تنتقل كافة البيانات والتعديلات بداخله تلقائياً 100%.

2. **التكامل المباشر حتى عند فتح الموقع بدون خادم (`file://`)**:
   - تم ربط البوابة بملف البيانات المتنقل **`data/saved_data.js`**.
   - حتى لو قام المستخدم بفتح ملف `index.html` مباشرة دون تشغيل الخادم، ستقوم البوابة بقراءة ملف البيانات المحدث داخل المجلد تلقائياً.

3. **واجهة إدارة وحفظ بيانات المجلد المدمجة**:
   - زر علوي دائم في شريط العنوان: **«حفظ ومزامنة المجلد»** يوضح حالة الاتصال (متصل بالخادم / يحتاج حفظ يدوي).
   - إمكانية تنزيل ملف `saved_data.js` المحدث بضغطة زر واحدة لحفظه بمجلد `data`.
   - إمكانية ربط مجلد الموقع بالمتصفح مباشرة عبر تقنية File System Access API.
   - إمكانية تصدير واستيراد نسخ احتياطية شاملة بصيغة JSON.

### 3. كيفية استرجاع البيانات التي قمت بتعديلها على جهازك الأول:
1. افتح الموقع على الجهاز الأول (الذي قمت بإضافة الطلاب عليه).
2. اضغط على الزر العلوي **«حفظ ومزامنة المجلد»** ثم اختر **«تصدير نسخة احتياطية (JSON)»** (أو «تنزيل ملف saved_data.js»).
3. انقل الملف الناتج إلى الجهاز الثاني (أو ضعه داخل مجلد `data` باسم `saved_data.js`).
4. افتح البوابة على الجهاز الثاني واضغط **«استيراد ملف بيانات»**، وستظهر كافة التعديلات والطلاب فوراً وبنجاح!

## الترقية المؤسسية لقاعدة البيانات والأمان (PostgreSQL JSONB & Security Upgrade)

تمت ترقية البنية التحتية للمنظومة لتشمل تصميم قاعدة بيانات **PostgreSQL** بنمط **JSONB** الهجين مع منظومة أمان ونسخ احتياطي وتماثل متكاملة:

### 1. تصميم قاعدة البيانات (PostgreSQL + JSONB)
- **`database/schema.sql`**: تصميم الجداول (`users`, `students`, `centers`, `audit_logs`, `portal_configs`) بالاعتماد على نوع البيانات `JSONB` للمرونة العالية مع أعمدة علائقية للمفاتيح والطوابع الزمنية وتريجر تحديث تلقائي.
- **`database/seed_data.sql`**: ملف البيانات الأولية الجاهز للاستيراد المباشر متضمناً الـ 40 حساباً رسمياً مشفرة بـ `bcrypt`، وسجلات الطلاب، والـ 164 مركزاً، وسجل التدقيق.
- **`database/migrate_to_postgres.py`**: أداة برمجية لترحيل البيانات من ملفات JSON وتوليد تجزئات `bcrypt` وإدراجها في PostgreSQL.

### 2. الفهرسة المتقدمة (Indexing)
- **`database/indexes.sql`**: يتضمن فهارس **B-Tree Expression** للبحث الفوري بالرقم القومي (`nid`) والفلترة بالمحافظة والإدارة والحالة والترتيب التنازلي، وفهارس **GIN (`jsonb_path_ops`)** لاحتواء الكائنات والمصفوفات، وفهارس **Trigram (`pg_trgm`)** لتسريع البحث النصي العربي في أسماء الطلاب والمدارس والمراكز.

### 3. الأمان والتحقق عبر الخادم (Server-Side Auth, Bcrypt & JWT)
- **`server.py`** و **`data/users_auth.json`**: نقل منطق التحقق من كلمة المرور إلى الخادم (`/api/v1/auth/login` و `/api/v1/auth/verify-2fa`)، وتخزين كلمات المرور كـ Hash باستخدام خوارزمية **bcrypt (`$2b$12$`)**، وإصدار رمز **JWT (HMAC-SHA256)** موثق بعد تسجيل الدخول.

### 4. النسخ الاحتياطي الآلي اليومي لموقع منفصل (Automated Off-Site Backup)
- **`database/backups/pg_backup_daily.sh`** (لينكس) و **`database/backups/pg_backup_daily.ps1`** (ويندوز) و **`database/backups/cron_schedule.txt`**: نسخ احتياطي آلي يومي بصيغة `pg_dump -Fc`، مع حساب بصمة التحقق `SHA-256`، والتشفير بـ `AES-256`، والنقل التلقائي إلى خادم منفصل أو سحابة خارجية (Off-Site Vault / S3).

### 5. النسخ المتماثل المباشر (PostgreSQL Streaming Replication)
- **`database/replication/primary_postgresql.conf`** و **`primary_pg_hba.conf`**: إعدادات الخادم الرئيسي لبث سجلات `WAL`.
- **`database/replication/setup_standby.sh`** و **`failover_promote.sh`**: إعداد الخادم الاحتياطي (`Hot Standby`) عبر `pg_basebackup -R -X stream` ومراقبة التزامن والترقية الفورية عند الطوارئ.
- **`docker-compose.yml`**: ملف تشغيل متكامل يرفع الخادم الرئيسي (Primary) والخادم الاحتياطي (Standby Replica) وخدمة النسخ الاحتياطي اليومي الآلي بضغطة واحدة (`docker compose up -d`).
